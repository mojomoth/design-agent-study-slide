# 탐색: 다양한 가능성의 발견

- 빈 화면에서 곧바로 한 방향을 완성하려 하지 말고, 먼저 서로 다른 시안을 넓게 살펴봅니다.
- 기법 1은 무작위 문자열을 활용하는 방법입니다. 셸 스크립트로 문자열을 만들고, 그 안의 패턴에서 색 조합과 배치, 글꼴의 방향을 찾게 합니다.
- 문자열 자체는 화면에 표시하지 않습니다. 서로 다른 문자열로 만든 시안을 비교해 발전시킬 방향을 고릅니다.
- 기법 2는 구체적이고 과감한 프롬프트를 쓰는 방법입니다. 픽셀 아트 게임, 3D 도시, 비대칭 배치처럼 원하는 경험을 설명합니다.
- 아이디어가 부족하면 AI에 짧은 아이디어를 많이 요청합니다. 마음에 드는 것을 그려 보고, 좋은 점과 싫은 점을 전달해 다듬습니다.
- 방향이 정해지면 초기 개념 검증용 페이지를 만들 프롬프트를 작성하게 합니다. 실패한 프롬프트도 남겨 두고 새로운 모델에서 다시 시험합니다.

# 구체화: 선택한 디자인 방향의 발전

- 기법 3은 별도 에이전트에게 디자인을 평가받는 방법입니다. 평가자에게 현재 스크린샷만 전달하고 코드와 이전 평가 내용은 주지 않습니다.
- 같은 기준과 좋은 디자인 사례로 평가받고, 구현 에이전트가 수정한 뒤 다시 확인합니다. 먼저 한두 번 시도하고, 반복을 끝낼 기준도 정합니다.
- 기법 4는 이미지 생성으로 개성을 더하는 방법입니다. 이미지 도구 사용을 분명히 요청하고, 필요하면 셰이더나 3D 효과와 함께 사용합니다.
- 생성한 이미지와 효과는 브라우저에서 확인합니다. API 키를 쓴다면 개발 환경에서만 사용하고 제품에는 포함하지 않습니다.
- 기법 5는 생성 영상을 화면의 움직임에 사용하는 방법입니다. 단색 배경의 반복 영상을 만든 뒤 크로마키나 영상 매팅으로 배경을 제거합니다.
- 상태 전환에는 앞 영상의 마지막 프레임을 다음 영상의 시작점으로 사용합니다. 스크롤이나 스와이프에 맞춰 프레임을 움직여 장면을 연결합니다.

# 마무리: 사용자가 좋아할 디자인의 완성

- 기법 6은 쓸모없는 요소를 지우는 방법입니다. 불필요한 효과와 상자, 중복 설명을 덜어내고 사용자가 필요한 내용에 집중하게 합니다.
- 칼로리 기록 앱은 사진 중심의 격자 배열로 정리하고 iOS 기본 구성 요소를 사용하자, 화면이 단순해지고 의도가 분명해졌습니다.
- 기법 7은 AI가 자주 반복하는 표현을 살피는 방법입니다. 제목 위 이름표, 흔한 그라데이션, 과한 카드와 글자 스타일이 필요한지 확인합니다.
- 처음부터 모두 금지하지는 않습니다. 이미지나 단색 배경, 단순한 격자 배치처럼 다른 방식을 적용한 뒤 결과를 비교합니다.
- 기법 8은 사람이 문구를 다시 쓰는 방법입니다. AI 문구는 임시 글로 보고, 모든 문장을 읽어 말투를 맞추고 불필요한 설명을 줄입니다.
- 마지막으로 사용 흐름이 자연스럽고 실제 목적에 도움이 되는지 판단합니다. 디자인의 완성도는 사용자가 느끼는 편리함과 즐거움으로 확인합니다.
