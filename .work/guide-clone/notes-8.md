# 1. 무작위 문자열을 활용한 다양한 시안 생성

- 같은 요청을 반복하면 AI는 익숙한 색과 배치를 되풀이합니다. “무작위로 만들어 달라”는 말만으로는 다양한 결과를 얻기 어렵습니다.
- 셸 스크립트로 영문자와 숫자가 섞인 긴 무작위 문자열을 생성합니다.
- 문자열 안의 패턴이나 특별한 숫자에서 색 조합, 배치, 글꼴의 방향을 찾게 합니다.
- 정한 방향을 실제 페이지로 구현하되, 문자열 자체는 화면에 표시하지 않습니다.
- 서로 다른 문자열로 만든 시안을 비교하고, 더 발전시키고 싶은 방향을 고릅니다.

# 2. 구체적이고 과감한 프롬프트 작성

- 픽셀 아트 게임, 3D 도시, 비대칭 배치처럼 직접 마음에 드는 대상을 고르고, 그 특징을 페이지에 어떻게 담을지 설명합니다.
- 아이디어가 떠오르지 않으면 AI에 세부 설명을 뺀 짧은 아이디어를 최대한 많이 요청합니다.
- 마음에 드는 아이디어를 머릿속에 그려 보고, 좋은 점과 싫은 점을 구체적으로 기록합니다. 제어판의 손맛은 좋지만 만화 같은 모습은 싫다는 식입니다.
- 취향을 전달해 아이디어를 다듬고, 만족할 때까지 방향을 조정합니다.
- 방향이 정해지면 초기 개념 검증용 페이지를 만들 수 있는 짧은 프롬프트를 작성하게 합니다.
- 안 될 것 같은 아이디어도 시험합니다. 실패한 프롬프트는 보관했다가 새로운 모델에서 다시 실행합니다.

# 3. 별도 에이전트의 평가를 통한 반복 개선

- 구현 에이전트와 평가 에이전트의 역할을 나눕니다. 평가자에게는 현재 화면만 주고 코드, 구현 과정, 이전 평가 내용은 전달하지 않습니다.
- 새 대화에서 같은 평가 요청을 사용합니다. 전체 구성과 작은 요소를 살피고, 부족한 부분을 짧고 구체적으로 짚게 합니다.
- 좋은 디자인 사례를 함께 보여주면 비교 기준이 분명해집니다. 참고 이미지는 그대로 복제할 대상이 아니라 품질을 판단할 기준으로 사용합니다.
- 구현 에이전트가 평가를 반영하고, 새 스크린샷을 다시 평가받습니다. 먼저 한두 번 수정해 방향이 좋아지는지 확인합니다.
- 반복을 끝낼 기준도 정합니다. 원문은 10점 만점에 9점 이상을 기준으로 삼되, 평가자에게는 이 기준을 알리지 않습니다.
- 판단이 필요한 평가에는 성능이 좋은 모델을 쓰고, 구현에는 방향을 충분히 이해하는 빠른 모델을 사용해 비용을 조절합니다.

# 4. 이미지 생성을 활용한 개성 표현

- 코드로 만든 단순한 도형이나 그라데이션만으로 화면이 밋밋하다면, 이미지 생성 도구를 사용하라고 분명히 요청합니다.
- 디자인 방향에 맞는 이미지를 만들고, 필요하면 셰이더나 3D 효과를 함께 사용합니다.
- 내장 도구가 있다면 그 도구를 사용합니다. 원문은 별도 이미지 API를 연결하는 방법도 설명합니다.
- API 키는 개발 환경에서만 사용합니다. 반복해서 쓴다면 Git에서 제외한 `.env.agents`에 저장하고, 제품에 포함하지 않는다는 규칙을 기록합니다.
- 이미지를 넣은 뒤에는 브라우저에서 결과를 확인합니다. 움직이는 효과는 프레임별로 보며 의도한 모습이 나오는지 점검합니다.

# 5. 영상 생성을 활용한 움직임 표현

- 단색 배경 위에 반복 재생 영상을 만들고, 배경을 제거해 페이지에 겹쳐 놓을 수 있는 애니메이션으로 사용합니다.
- 단순한 배경은 크로마키로 지웁니다. 더 복잡한 장면에는 영상 매팅 모델을 사용합니다.
- 유리 굴절처럼 배경의 영향을 받는 효과는 실제 페이지 배경색 위에서 먼저 생성한 뒤 배경을 제거합니다.
- 상태가 바뀌는 장면은 순서를 먼저 정합니다. 원문의 여행 가방은 공중에 떠 있다가 내려앉고, 뚜껑이 열린 뒤 짐이 담깁니다.
- 첫 이미지를 만든 뒤 다음 상태로 이어지는 영상을 생성합니다. 마지막 프레임을 다음 영상의 시작점으로 사용해 장면을 연결합니다.
- 사용자의 스크롤이나 스와이프에 맞춰 영상을 프레임 단위로 움직이면, 화면 전환을 직접 조작하는 경험을 만들 수 있습니다.

# 6. 쓸모없는 요소의 삭제

- “간결하게 만들어 달라”고 요청한 뒤에도 실제로 필요한 요소가 무엇인지 사람이 다시 판단합니다.
- 이유 없이 넣은 발광 효과, 그라데이션, 글자 색과 강조 표시를 줄입니다.
- 사진만으로 내용을 알 수 있다면 같은 뜻을 반복하는 설명과 불필요한 빈 공간을 없앱니다.
- 칼로리 기록 앱은 사진 중심의 격자 배열로 정리하고, 따로 만든 버튼과 입력창을 iOS 기본 구성 요소로 바꿨습니다.
- 글자와 화면 구성을 단순하게 정리한 뒤, 중요한 내용이 더 잘 보이고 사용 흐름이 자연스러운지 확인합니다.

# 7. AI가 반복하는 표현 방식의 정리

- 제목 위에 작은 이름표가 붙어 있다면, 제목과 같은 말을 반복하는지 확인하고 필요 없는 것은 지웁니다.
- 흔한 배경 그라데이션은 제품에 맞는 이미지, 패턴, 단색 배경으로 바꿔 비교합니다.
- 카드와 상자가 너무 많으면 격자나 타일처럼 단순한 배치로 정리합니다.
- 글꼴은 1~2개, 글자 스타일은 2~4개에서 시작합니다. 강조 색과 기울임꼴은 필요한 곳에만 사용합니다.
- 이런 표현을 처음부터 모두 금지하지는 않습니다. 쓰는 이유가 분명한지 확인하고 마무리 단계에서 다른 방식과 비교합니다.

# 8. 사람이 직접 고치는 문구

- AI가 처음 쓴 문구는 화면 구성을 확인하기 위한 임시 글로 취급합니다.
- 사람이 모든 문장을 읽고, 제품 전체에서 말투가 일관되도록 다시 씁니다.
- 긴 비유와 반복되는 설명을 줄이고, 제품이 무엇을 하며 사용자에게 어떤 도움을 주는지 쉽게 설명합니다.
- 원문의 데이터베이스 도구 소개도 길게 풀어 쓴 상황 설명을 줄이고, 성능 문제를 찾는 기능과 사용 방법을 직접 설명하도록 고쳤습니다.
- 문장을 짧게 만드는 데서 끝내지 않고, 뜻이 분명한지와 사용자가 실제로 읽을 만한 내용인지 확인합니다.
